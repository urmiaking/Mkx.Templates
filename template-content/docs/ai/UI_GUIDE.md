# UI and interaction

Use semantic HTML, native Blazor controls and the primitives in `Components/UI`. The application has no external component-library runtime. The design follows the reference workspace: navy `#123D51`, teal `#187F87`, blue-grey background `#F4F8FB`, white opaque surfaces, rounded controls and 16â€“17px panels. Use central `app.css` and semantic `--ui-*` tokens, including persisted light/dark appearance. Dark mode uses charcoal surfaces, saturated jade action backgrounds and brighter mint links. Vazirmatn is the primary local font, with IRANSans as fallback; no remote font request is required.

The root enables Vazirmatn's `ss01` OpenType feature so Latin digit code points render with Persian numeral glyphs, including tables, dates, counts and form controls. Preserve raw numeric values, URLs, OTP normalization, clipboard contents and API payloads; do not rewrite DOM text or bound values to localize their appearance.

Non-trivial pages use markup/code-behind, `AppComponentBase`, shared routes and policies. Use `TryRequestAsync` with explicit loading, empty, error and retry states. Client visibility never replaces server authorization.

## Forms
`UiTextField` renders labeled native inputs/textareas; `UiCheckBox` and `UiSelect` use native controls. Interactive `UiForm.ValidateAsync()` collects required, DataAnnotations property and existing FluentValidation field rules. `For` expressions integrate with an enclosing EditContext. Native `EditForm` + `InputText`/`InputCheckbox` serve static SSR account pages and preserve form field names, antiforgery and server form mapping. Do not inject interactive-only services into static SSR pages. Preserve password-manager autocomplete, paste and LTR numeric input modes.

Keep busy actions disabled, retain input on failed saves and show field/request errors. `Tests/SampleItemEditor` demonstrates versioned updates, duplicate-submit guards and dirty navigation/cancel protection. A failed request must allow correction and retry.

The recovery phone field uses one bordered wrapper around its icon and native telephone input. Keep the input border and shadow reset more specific than the global input styles; show focus on the wrapper with `:focus-within`.

## OTP fields
Reuse `UiOtpField` for password recovery, phone-change verification and authenticator setup. It presents six visual cells over one labeled native input, preserving full-code paste, password-manager/SMS autofill, leading zeros, numeric keyboard and LTR order. Both JS and `OtpCode.Normalize` accept Persian/Arabic digits. Decorative cells are hidden from assistive technology. `Sms=false` prevents WebOTP requests for authenticator codes.

Static SSR recovery gives the input its native `Input.OtpCode` name and opts into native form autosubmit; request/resend/verify submitter names, antiforgery tokens and server-side cooldown/verification must remain intact. Interactive fields bind to the existing model; use `OnCompleted` only for a guarded verification action. The shared JS initializes on initial load, enhanced navigation and interactive insertion. Do not create six separately focusable inputs or block paste.

## Dialogs and messages
`DialogService` hosts dynamic component dialogs via `UiDialogHost`. `UiModal` uses native `dialog.showModal()` and the browser top layer, focus containment, Escape/backdrop policies and focus restoration from `js/modal.js`. Dirty editors disable direct backdrop/Escape closing and run their explicit discard confirmation. Nested confirmations must restore focus to the editor. The content scrolls within `dvh` bounds and the action footer remains reachable. `ToastService` displays dismissible live-region messages; messages contain actual outcomes.

## Tables
`UiTable<T>` renders a semantic table, with labeled stacked rows below 650px and server paging controls. It cancels stale requests and prevents stale results from replacing newer data. Keep initial pages <=25 rows and page sizes <=100. Search uses cancellable debounce. Sorting is server-side through `TableState`; mutations reload the current page, adjusting a now-empty last page. Every icon action needs an accessible name.

## Role permissions
`Users/RoleClaims` uses a single roles surface with flat, separated rows: identity, real member/permission counts and a clearly labeled manage action. On smaller screens statistics move below the identity/action row. Do not wrap a responsive table/card inside another panel. Distinguish loading, empty, disabled and failed requests and keep retry available.

The shared `ClaimsTreeDialog` uses a labeled search and bulk actions aligned at the input baseline, compact native checkbox lists, semantic fieldsets and one modest indentation per tree level. Avoid individual node cards, repeated key icons and always-visible technical identifiers; identifiers remain searchable and available as titles. Desktop choices are at least 40px high, mobile choices at least 44px. Bulk selection includes hidden/filter-excluded permissions; filtering never modifies selection. Artificial Category_ nodes are excluded from the saved claim list. Role saves execute before closing the dialog via its SaveChanges callback; failures retain selections and show an inline retryable error. The shared modal owns scrolling and keeps its action footer reachable.

## Navigation and motion
MainLayout supplies a skip link and stable `#main-content` route-focus target. The desktop sidebar is fixed at 238px, with brand, primary create action, full nav labels and account controls. The 82px topbar lives inside the workspace. Below 960px, the sidebar slides over a scrim, traps keyboard focus, makes background content inert and closes on navigation/Escape. The mobile bottom bar has a raised central create action and safe-area padding. Its create link opens the actual Tests editor through the shared create query route. Notifications use a full-height native dialog at the left edge (420px desktop, full width on phones), with summary, list/empty state and footer. It is an extension surface; do not add fake counts or delivery settings without a notification service.

AccountShell provides a breadcrumb, overline, title, description, actions and grouped body. Account overview combines profile rows, security tiles and a separate sign-out section. Static SSR identity pages use a centered 440px card with a grouped section entrance. Page entry applies on phones, tablets and desktop: 340ms opacity with 380–500ms coordinated header/body reveals, including tables and toolbars inside `account-body`. Home uses the same grouped entry for its layout and guide. Keep motion rules outside layout breakpoint queries so changing viewport does not disable them. Animate the shared body once rather than stacking panel/row entrances, and never key/remount routed content to replay motion. Controls keep brief interaction feedback. Respect `prefers-reduced-motion` automatically on every screen size. Avoid blur, continuous decorative motion, transition:all and layout animation.

The theme button passes its element to ThemeService. On browsers supporting same-document View Transitions, dark mode expands as an 800ms circle from the button center to the furthest viewport corner. Returning to light reverses the motion and easing: the old dark snapshot contracts back into the button, with light already underneath. Keep the dark snapshot on top in both directions. Hold the clip with `fill: both` until `ViewTransition.finished`, then cancel the retained animation to release it; clearing the clip at animation completion can flash the entire old dark snapshot before the browser removes it. System/initial appearance, reduced motion and unsupported browsers apply immediately. Keep the snapshot CSS scoped to the theme transition, suppress competing control transitions during the reveal, and disable duplicate toggles until it completes. Appearance still persists when local storage is available.

## Color palettes and appearance controls
The independent `Theme.Palette` preference supports jade (default), ocean, iris and amber in both light and dark mode. Keep palette colors in central `app.css` semantic tokens; success/error/warning retain their meaning. Startup validates/restores the palette before WASM initializes, including static SSR account pages. Mode and palette never reset each other.

`PalettePicker` lives only at the left edge. Its visible droplet is 32px wide with a 44px hit box, no grip bar, and mouse/pen dragging through Pointer Events and a separate non-passive Touch Events path on phones. Touchstart suppresses native browser scrolling/callouts; document-level touchmove/end/cancel continue beyond the hit box without requiring pointer capture. A short tap explicitly activates the native popover once, and delayed compatibility clicks are suppressed. A 6px movement threshold distinguishes dragging from clicking; pointer capture keeps motion working beyond the tab. Persist a clamped 0–1 vertical fraction in `Theme.PickerPosition`, restore it across reload/navigation and adapt it to the current viewport between the header and mobile bottom navigation. Arrow keys move by 24px; Home/End reach the available limits. Storage failure must not disable the control.

The native auto popover grows directly from the droplet as a curved SVG-backed sheet with a neck centered on the tab. Its transform origin follows the tab even at viewport limits. Opening and closing (close button, Escape or light dismiss) reverse the same 440ms scale/opacity transition; reduced motion skips it. Native dismissal/focus behavior remains intact. Keep the tab inert behind mobile navigation and below modal layers. The body scrolls within the visual viewport while the shell remains attached to the edge. Mobile toolbar controls retain 44px touch boxes with 8px gaps.

On mobile (below 960px), the sheet has an icon to hide the floating control. Close the sheet with its reverse animation before hiding, move focus to the menu trigger, and persist `Theme.MobilePickerHidden` independently of position, palette and mode. Startup restores this preference before the app renders. It applies only to mobile; desktop keeps the edge picker. Above the account section in mobile navigation, show four labeled-for-accessibility color swatches without visible text, with a check for the selected palette. An eye button beside them can show/hide the tab again. Give all five controls equal column widths and 44px touch boxes, center each swatch/check/icon in both axes, and suppress the gallery-style hover lift on these compact buttons. These controls stay outside the navigation-link click-to-close container so choosing a color keeps the menu open. Both entry points use ThemeService and the same circular reveal; the navigation swatch group supplies its own origin.

Explicit palette changes use the same root snapshot helper as light/dark, revealing the new palette in an 800ms circle from the moved tab in both modes. Swap all tokens atomically inside the snapshot update and suppress competing transitions on controls and pseudo-elements. Do not interpolate inherited color properties: borders, hover rings and aliases can otherwise show intermediate white/black halos. Mode reversal still contracts the old dark snapshot; palette changes always expand the new snapshot. Both retain their final clip through snapshot removal. Initial restoration, reduced motion, rejected snapshots and unsupported browsers apply immediately; interrupted reveals must preserve the newest choice. Do not remount routed content or add per-element animation.
