# Native Blazor UI and shared workspace design

The generated application uses native HTML and Blazor controls with a small reusable `Components/UI` layer. Its visual reference is the MeetFlow workspace: Persian RTL, local Vazirmatn, navy/teal accents, opaque surfaces, soft borders, full-label navigation and brief interaction feedback. Product-specific meeting/calendar features do not belong in this general-purpose template.

Appearance is expressed by CSS tokens in `app.css`, with persisted light/dark preference. Account endpoints retain static SSR and native form mapping; application pages retain Interactive WebAssembly without prerendering. Existing service contracts, policies and architecture boundaries remain authoritative.

Dialogs use the browser top layer and native focus behavior, supplemented by explicit close policy, focus restoration and mobile scroll bounds. Desktop navigation uses the reference’s permanent 238px sidebar and workspace-only topbar. Mobile uses a full-height overlay with keyboard containment and a safe-area-aware bottom bar with raised center action. Notifications open as a full-height left-side panel, not a compact popup. Page-entry animation applies to fresh page roots, without keying/remounting routed content when the layout receives a location event. This avoids cancelling a page's first load merely to animate it.

The shared form layer validates required values, property annotations and existing field validators before making requests. Explicit string values use Razor expressions; binding syntax and server-generated input names are preserved. The reference OTP presentation is shared across SSR recovery, phone verification and authenticator setup. One real input preserves paste/autofill; Persian/Arabic digits normalize in both client and server paths. Regression checks cover required/property validation, native SSR input names, real recovery POST/cooldown/verification, OTP request locking and the existing API/PWA suites. Browser checks use intercepted fixture data for UI interaction; actual persistence/authorization are covered by the SQLite integration suite.
